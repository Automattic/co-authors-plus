# Filters and actions

This page is a reference for the hooks that Co-Authors Plus provides. It is generated by reading the source, so if you find something out of date, grep for `apply_filters` and `do_action` in the repo and please open a PR.

File paths are relative to the plugin root.

For task-based examples of the most common filters, see [Customizing Co-Authors Plus](./customizing.md).

## Display and formatting

### `coauthors_default_before`

Text placed before a list of co-authors. The template tags default to `''`. The Co-Authors block uses this filter for the default of its `prefix` attribute, which is `'By '`.

In the template tags, the four separator defaults can also come from the `COAUTHORS_DEFAULT_BEFORE`, `COAUTHORS_DEFAULT_BETWEEN`, `COAUTHORS_DEFAULT_BETWEEN_LAST` and `COAUTHORS_DEFAULT_AFTER` constants. When a constant is defined, its value is what the filter receives. The block ignores the constants.

- **Type:** `string`
- **Used in:** template tags and the Co-Authors block
- **Files:** `template-tags.php`, `php/blocks/block-coauthors/class-block-coauthors.php`

### `coauthors_default_between`

Separator between co-authors (all but the last). Defaults to `', '` in both the template tags and the Co-Authors block (its `separator` attribute).

### `coauthors_default_between_last`

Separator before the final co-author. Defaults to `' and '` (translatable) in both the template tags and the Co-Authors block (its `lastSeparator` attribute).

### `coauthors_default_after`

Text placed after a list of co-authors. Defaults to `''` in both the template tags and the Co-Authors block (its `suffix` attribute).

### `coauthors_posts_link`

Arguments used to render a single co-author's posts-link. Filter the associative array to customise the markup emitted by `coauthors_posts_links()`. Available keys include `before_html`, `href`, `rel`, `title`, `class`, `text`, and `after_html`.

- **Parameters:** `array $args`, `stdClass $author`
- **File:** `template-tags.php`

### `coauthors_wp_list_authors_array`

The array of authors built by `coauthors_get_users()`, which `coauthors_wp_list_authors()` uses to build its listing. Use this to filter the listing rather than post-process the output. The array is keyed by the author term's name (the author's `user_login`).

- **Parameters:** `array $authors`
- **File:** `template-tags.php`

### `get_coauthors`

The resolved co-authors for a post. Runs after the plugin's lookup but before any display logic.

- **Parameters:** `array $coauthors`, `int $post_id`
- **File:** `template-tags.php`

### `coauthors_open_graph_tags`

The Open Graph tags after Co-Authors Plus has adjusted Jetpack's tags. The plugin hooks Jetpack's `jetpack_open_graph_tags` filter to set the author archive tags (and `article:author` on single posts) from the co-author, then passes the result through this filter. It only runs when Jetpack outputs Open Graph tags.

- **Parameters:** `array $og_tags`
- **File:** `php/class-coauthors-plus.php`

### `coauthors_auto_apply_template_tags`

Return `true` to make the core `the_author()` and `the_author_posts_link()` output all co-authors, and to list every co-author as a `dc:creator` in RSS2 feeds. Defaults to `false`. Useful when you can't edit the theme. Read once on `init`, so add the filter before `init`.

- **Parameters:** `bool $apply` (defaults to `false`)
- **Files:** `php/class-coauthors-plus.php`, `php/class-coauthors-template-filters.php`

## Post type and taxonomy configuration

### `coauthors_supported_post_types`

Post types that Co-Authors Plus attaches to. Defaults to every registered post type that supports `author`, minus `revision`, `attachment`, `customize_changeset`, `wp_template`, `wp_template_part` and `wp_block`. Note that this is not the same as the public post types: a post type is included on its `author` support alone, whether or not it is public, and a public post type registered without `author` support (WooCommerce's `product`, for example) is not included.

The `author` taxonomy is registered for this list on `init` at priority 100, so a post type must have its `author` support in place by then — `add_post_type_support()` called later leaves the post type out of the taxonomy, and the plugin's author query filters will skip it.

The list is recomputed on every call until `wp_loaded`, then memoised for the remainder of the request. A callback on this filter should therefore not depend on request context that is only settled later, such as the current query or screen.

- **Parameters:** `array $post_types`
- **File:** `php/class-coauthors-plus.php`

### `coauthors_count_published_post_types`

Post types counted towards a co-author's published post count.

- **Parameters:** `array $post_types` (defaults to `[ 'post' ]`)
- **Files:** `php/class-coauthors-plus.php` (two call sites)

### `coauthors_default_author`

The `WP_User` used as the default author when a post has none. Defaults to the current user.

### `coauthors_post_author_value`

The user ID to save in the `post_author` column when a post of a supported type is saved (autosaves are skipped). It runs on core's `wp_insert_post_data` filter after the plugin has worked out the value, so it can force `post_author` to a generic user. It does not change the post's co-authors.

- **Parameters:** `int $post_author`, `int $post_id` (`0` for a new post)
- **File:** `php/class-coauthors-plus.php`

### `coauthors_plus_is_author_query`

Whether Co-Authors Plus should rewrite an author query to include co-author taxonomy terms. By default this is `true` for author archives and for queries that set `author`, `author_name` or a non-empty `author__in`. Returning `false` leaves the query as a standard WordPress `post_author` query, for example for a report of who created each post.

- **Parameters:** `bool $is_author`, `WP_Query $query`
- **File:** `php/class-coauthors-plus.php`

### `coauthors_plus_should_query_post_author`

Whether author queries match on the `post_author` column as well as the `author` taxonomy. Defaults to `true`. Returning `false` switches to a simpler taxonomy-only query on sites where `post_author` isn't reliable. Posts with no co-author terms then drop out of author archives, so give them co-authors first. Find them with `wp co-authors-plus list-posts-without-terms`, fix the bylines where `post_author` is wrong, and only then run `wp co-authors-plus create-author-terms-for-posts` for the rest. That backfill takes the co-author from `post_author` and skips posts that already have author terms, so running it on posts with a wrong `post_author` writes the wrong byline and a later run won't correct it. Unlike the older `create-terms-for-posts`, which covers every supported post type, it only covers published posts of the `post` post type unless you pass `--post-types` and `--post-statuses`. See [How do I stop author archives from matching on `post_author`?](./customizing.md#how-do-i-stop-author-archives-from-matching-on-post_author) for the steps.

The value is also read when the taxonomy is registered (on `init` at priority 100) to choose how term counts are kept, so add the filter before `init` and don't change it per request. Author queries treat it as `false` while `coauthors_guest_authors_force` is on.

- **Parameters:** `bool $should_query` (defaults to `true`)
- **File:** `php/class-coauthors-plus.php`

## Permissions

See [Roles and capabilities](./roles-and-capabilities.md) for how these filters fit together.

### `coauthors_plus_edit_authors`

Whether the current user can assign co-authors. Defaults to the post type's `edit_others_posts` capability, such as `edit_others_pages` for pages, or `edit_others_posts` when the post type isn't known. Super admins can always assign co-authors, and the filter is not applied for them.

The filter receives the post type the co-authors are set on, or `null` when it isn't known. It does not receive the post itself. See [Roles and capabilities](./roles-and-capabilities.md#assigning-co-authors) for every place this check runs, and for an example that lets the Author role assign co-authors.

- **Parameters:** `bool $can_set_authors`, `string|null $post_type` (the post type, or `null` when it isn't known)
- **File:** `php/class-coauthors-plus.php`

### `coauthors_edit_author_cap`

Capability required to appear in the co-author search results. Defaults to `edit_posts`. The same capability limits the users offered in the guest author "WordPress User Mapping" dropdown.

### `coauthors_edit_ignored_authors`

Array of `user_nicename` values hidden from the co-author search results. Defaults to the co-authors the search request asked to exclude (usually the ones already on the post).

- **Parameters:** `array $ignored_authors`
- **File:** `php/class-coauthors-plus.php`

### `coauthors_rest_view_description_cap`

Capability required to see the `description` of an author term in core's `/wp/v2/coauthors` responses. Defaults to `list_users` (`edit_posts` before 4.1.3). For users without it, the `description` key is removed from the response. Since 4.2.0 the endpoints themselves need `edit_posts`, so a capability below that has no effect. The term description holds the plugin's search index for the author, which can include the email address. This filter does not affect the `coauthors/v1` endpoints.

- **Parameters:** `string $capability`
- **File:** `php/class-coauthors-plus.php`

## Guest authors

### `coauthors_guest_authors_enabled`

Whether the guest authors feature is active. Return `false` to disable entirely.

### `coauthors_guest_authors_force`

Whether bylines come from co-author terms only, with no fallback to the post's `post_author` user. Defaults to `false`. Useful when every byline is a guest author and WordPress accounts are used only to log in.

When `true`:

- `get_coauthors()` returns an empty array for a post with no co-authors, instead of the `post_author` user.
- Author archive queries ignore the `post_author` column, as if `coauthors_plus_should_query_post_author` returned `false`.
- In the classic editor, the Authors box on a new post is not filled with the current user. It still shows the guest author linked to the current user, if there is one.

It does not stop `save_post` from adding the post's `post_author` as a co-author when a post is saved with none, so it mostly affects older posts that have no co-author terms.

The value is read once on `init` at the default priority, and only when guest authors are enabled, so add the filter before `init`.

- **Parameters:** `bool $force` (defaults to `false`)
- **File:** `php/class-coauthors-plus.php`

### `coauthors_guest_author_manage_cap`

Capability required to manage guest authors, and to change which user a guest author is linked to. Defaults to `list_users`. Deleting a guest author also needs `delete_post` on the profile, on the confirmation screen and when the deletion runs, whatever this filter returns. See [Roles and capabilities](./roles-and-capabilities.md).

### `coauthors_guest_author_parent_page`

Admin menu parent under which the Guest Authors UI appears. Defaults to `users.php`.

### `coauthors_guest_author_labels`

Labels for the `guest-author` post type and the Guest Authors screens. The array has the keys `singular`, `plural`, `all_items`, `add_new_item`, `edit_item`, `new_item`, `view_item`, `search_items`, `not_found`, `not_found_in_trash`, `update_item`, `metabox_about`, `featured_image`, `set_featured_image`, `use_featured_image` and `remove_featured_image`.

- **Parameters:** `array $labels`
- **File:** `php/class-coauthors-guest-authors.php`

### `coauthors_guest_author_linked_account_args`

Arguments passed to `wp_dropdown_users()` for the "WordPress User Mapping" dropdown on the guest author edit screen. By default it excludes users already linked to another guest author and lists only users with the `coauthors_edit_author_cap` capability.

- **Parameters:** `array $args`
- **File:** `php/class-coauthors-guest-authors.php`

### `coauthors_guest_author_fields`

Array of field definitions rendered on the guest author profile screen.

- **Parameters:** `array $fields`, `array $groups`
- **File:** `php/class-coauthors-guest-authors.php`

### `coauthors_guest_author_sortable_columns`

Sortable columns in the Guest Authors list table.

- **Parameters:** `array $sortable_columns`
- **File:** `php/class-coauthors-wp-list-table.php`

### `coauthors_guest_author_query_args`

`WP_Query` args used to list guest authors in the admin.

### `coauthors_guest_author_manage_columns`

Columns shown on the Guest Authors list table.

### `coauthors_guest_author_row_actions`

Row actions shown below each guest author in the list table.

- **Parameters:** `array $actions`, `object $item` (the guest author)

### `coauthors_show_create_profile_user_link`

Whether to show a "Create Profile" row action on the Users list for users who have no guest author profile yet. The action creates a guest author linked to that user. Defaults to `false`. Users who already have a profile always get an "Edit Profile" action.

### `coauthors_guest_author_personal_export_extra_data`

Extra data to include when exporting a guest author's personal data (WordPress privacy tools). Return an array of `name` and `value` pairs; they are added to the guest author's export item, after the profile fields. The export already includes every profile field with a value, including fields added with `coauthors_guest_author_fields`, so use this filter for data stored elsewhere.

- **Parameters:** `array $extra_data` (empty by default), `int $author_id`, `string $email_address`
- **File:** `php/class-coauthors-guest-authors.php`

### `coauthors_name_field_type_{$field}`

Dynamic filter per field, used to switch the input type of a field on the guest author profile form. Defaults to the field's `input` value, or `text` in the Name and Contact Info boxes and `textarea` in the About box. Returning `checkbox` renders a checkbox in the Name and Contact Info boxes, and returning `editor` renders the classic visual editor in the About box. The suffix is the field's post meta key, which carries the `cap-` prefix, for example `coauthors_name_field_type_cap-website`. See [Can I use a visual editor for the guest author bio?](./customizing.md#can-i-use-a-visual-editor-for-the-guest-author-bio)

- **Parameters:** `string $input`
- **File:** `php/class-coauthors-guest-authors.php`

## Meta box

### `coauthors_meta_box_title`

Title of the Authors meta box. Defaults to `Authors`.

### `coauthors_meta_box_context`

Where the meta box appears (`normal`, `side`, `advanced`). Defaults to `side`.

### `coauthors_meta_box_priority`

Meta box priority. Defaults to `high`.

### `coauthors_search_authors_get_terms_args`

Arguments for the `get_terms()` call that finds co-authors when searching. Defaults to `search` (the search text), `get` (`all`) and `number` (`10`). Raise `number` to return more than 10 results. This search backs the classic editor meta box, the block editor's `coauthors/v1/search` endpoint and the guest author screens.

- **Parameters:** `array $args`
- **File:** `php/class-coauthors-plus.php`

### `coauthors_ajax_suggest_author_data`

One author result in the classic editor search-as-you-type list. Each result has `id`, `login`, `label`, `value`, `email`, `nicename` and `avatar`. The list shows the avatar and `label`, but the whole result is sent to the browser. The classic editor has no JS label filter, so this is the way to change what the list shows, or to remove values like the email address. The `label` can be output as HTML, so keep it plain text. The `nicename` key can't be changed, because it is the value saved with the post. A non-array return is ignored. See [Can I show more about each author in the co-author search?](./customizing.md#can-i-show-more-about-each-author-in-the-co-author-search) and [Can I hide email addresses in the co-author search?](./customizing.md#can-i-hide-email-addresses-in-the-co-author-search) for examples.

- **Parameters:** `array $result`, `WP_User|object $author`
- **File:** `php/class-coauthors-plus.php`

## Blocks

### `coauthors_plus_support_blocks`

Return `false` to stop Co-Authors Plus from registering its blocks. Useful when a site wants to hide them from the inserter.

- **File:** `php/blocks/class-blocks.php`

### `coauthors_blocks_store_data`

Server-side example data passed to block editor placeholders when no authors are loaded yet. The array has one key, `authorPlaceholder`, an author shaped like a `coauthors/v1/coauthors` response item.

- **Parameters:** `array $data`
- **File:** `php/blocks/class-blocks.php`

### `co-authors-plus.author-placeholder` (JavaScript)

Client-side equivalent of `coauthors_blocks_store_data`. Applied via `@wordpress/hooks`.

- **File:** `src/blocks-store/index.js`

## REST API

### `rest_coauthors_item_schema`

Schema for a single co-author resource returned by the REST controller.

- **File:** `php/api/endpoints/class-coauthors-controller.php`

### `rest_prepare_coauthor`

The `WP_REST_Response` for a single co-author, after the default preparation. Use this to add custom fields.

For a registered user, `$author` is the user's data object (`WP_User::$data`), not the `WP_User` itself. For a guest author it is the guest author object.

- **Parameters:** `WP_REST_Response $response`, `object $author`, `WP_REST_Request $request`

### `rest_coauthors_prepare_items`

The resolved co-authors for a post, before the `coauthors/v1/coauthors` collection endpoint formats them for a REST response. Use this to limit, reorder, or replace the list that endpoint returns. The Co-Authors block's server render and the block editor both read from this endpoint, so their output follows the filtered list; headless clients and other plugins that query the same endpoint see it too.

This is presentation filtering only: co-authors removed here still exist on the post and remain visible through `get_coauthors()`, the byline template tags, the post's `coauthors` REST field, and the Authors panel in the editor sidebar. Do not use this filter for access control.

When you need to change the co-authors everywhere the plugin resolves them, filter `get_coauthors` instead — it runs earlier and applies to template tags and archives as well. Reach for `rest_coauthors_prepare_items` only when the change should affect the REST collection response.

Returning a non-array from the callback yields an empty response. Entries that are not valid co-author objects are dropped, and the surviving entries are reindexed so the response is always a well-formed JSON array.

- **Parameters:** `array $coauthors`, `int $post_id`, `WP_REST_Request $request`
- **File:** `php/api/endpoints/class-coauthors-controller.php`

### `coauthors_rest_author_data`

Author data the block editor gets for search results and the post's selected co-authors. Each entry has `id`, `termId`, `userNicename`, `login`, `email`, `displayName`, `avatar` and `userType`. The whole entry is passed to the [`coAuthors.formatAuthorData.label`](#coauthorsformatauthordatalabel) JS filter, so a key added here can be shown in the author option. Values can also be removed, like the email address; the sidebar then shows only the display name. The `id`, `termId` and `userNicename` keys can't be changed, because the editor needs them to save the co-authors. A non-array return is ignored. See [Can I show more about each author in the co-author search?](./customizing.md#can-i-show-more-about-each-author-in-the-co-author-search) and [Can I hide email addresses in the co-author search?](./customizing.md#can-i-hide-email-addresses-in-the-co-author-search) for examples.

- **Parameters:** `array $data`, `WP_User|object $author`
- **File:** `php/class-coauthors-endpoint.php`

## JavaScript filters (`@wordpress/hooks`)

### `coAuthors.formatAuthorData.label`

Label for an author option in the sidebar autocomplete. Defaults to `"{displayName} | {email}"`, or just `"{displayName}"` when the email is empty.

- **Parameters:** `string $label`, `object $author`
- **File:** `src/utils.js`

### `coAuthors.search.threshold`

Number of characters before the sidebar autocomplete begins searching. Defaults to `2`.

- **File:** `src/components/co-authors/index.jsx`

## Actions

### `cap_guest_author_create`

Fires after a guest author is created from an existing user with the "Create Profile" action on the Users list. It does not fire when a guest author is added from the Guest Authors screen, or from WP-CLI.

- **File:** `php/class-coauthors-guest-authors.php`

### `cap_guest_author_del`

Fires after a guest author is deleted from the Guest Authors screen. It does not fire when code calls `CoAuthors_Guest_Authors::delete()` directly.

### `coauthors_guest_author_custom_columns`

Fires while rendering a custom column for a guest author row.

- **Parameters:** `string $column_name`, `int $author_id`
- **File:** `php/class-coauthors-wp-list-table.php`

## Using these hooks

- Many of these hooks run in the admin, REST requests, the front end, cron and WP-CLI. Don't assume a current user, a global `$post` or an admin screen exists; check before you rely on them.
- Inside a callback, use `get_coauthors()` and `is_coauthor_for_post()` (see [Template tags](./template-tags.md)) rather than querying `post_author` yourself. They already handle the `author` taxonomy and the `post_author` fallback.

## Deprecated

### `coauthors_post_list_pluck_field`

Deprecated in 4.0 when triggered from a REST save. Use the `set_object_terms` action on the `author` taxonomy instead. See [Upgrading to 4.0](./upgrading-to-4.0.md).

### `coauthors_post_get_coauthor_by_field`

Deprecated in 4.0 when triggered from a REST save. Same replacement as above.
